# kid-memory：给小朋友的内存启蒙插件

**关键词**: DeepSeek Harness、Cordis 插件、kidlab 系列、少儿编程、内存启蒙、动态插件、工作台隐喻

## 核心结论（30秒速览）

- 我们为 kidlab 电脑启蒙系列开发了第五款插件 **kid-memory**（`@kidlab/dsh-kid-memory`），给小朋友讲「内存 = 电脑的工作台 / 大脑的短期记忆」这条故事线，正好跟 kid-storage 的"大仓库（长期记忆）"配成一对。
- 4 个工具全部**真执行命令**，覆盖工作台大小、现在摊了多少、谁在占地方、挤不挤，全部免 sudo、硬编码命令常量、单命令超时容错。
- 真机验证踩透两个"非逻辑"的坑：命令沙箱拦截 `top/ps`（改用 `memory_pressure` + `python3/libproc` 读 RSS），以及 `<span>` 进度条 `width` 失效（加 `display:block`）；并做了**按 App 聚合**的占用榜展示口径迭代。

## 1. 背景：第五款插件讲什么

kidlab 系列已经给小朋友做了解释代码、体检电脑、认识网络、看懂存储四款插件。这一款补上最抽象、也最不好讲的一块——**内存（Memory，记忆/存储单元）**。

内存看不见摸不着，跟小朋友说"内存条""RAM"几乎等于没说。我们想了个办法：**把内存比作电脑的工作台，也像大脑的短期记忆**——正在做的程序都摊在这张工作台上。

这个隐喻还刚好跟 kid-storage 的"大仓库（长期记忆）"凑成一对：**内存管"正在做的"，硬盘管"长期存放的"**。关掉不用的程序，就像把玩具收回大仓库，工作台就腾出空位来。

## 2. 主体：四把"内存小铲子"

我们用 **B 型真执行命令**范式做工具——工具真的去读这台电脑的内存数据，而不是让模型编。一共四个工具，全部**免 sudo、硬编码命令常量（不拼接用户输入）、单命令超时容错**：

| 工具 | 作用 | 底层命令 |
|---|---|---|
| `mem_workbench` | 工作台多大（总内存） | `sysctl -n hw.memsize` |
| `mem_now` | 现在摊了多少（已用/空闲/占用%） | `top -l 1 -n 0 \| grep PhysMem` |
| `mem_top` | 谁在占工作台（进程 RSS Top） | `ps -axo rss=,comm= \| sort -rn` |
| `mem_pressure` | 工作台挤不挤（内存空闲率） | `memory_pressure -Q` |

设计上有几个值得一提的点：

- **单位统一**：三个来源口径不同（`hw.memsize` 给字节、`ps` 给 KB、`top` 给 MB），我们各自换算成小朋友能看的 GB/MB。
- **口径澄清的软处理**：macOS 的"已用"里藏着一部分可随时释放的缓存，所以会看到 `mem_now` 显示 90%+ 已用、`mem_pressure` 却还说有一半空着。我们在已用率偏高时补一句温柔的安慰："别担心，电脑会自动把暂时不用的东西先放到一边，需要时再腾出来。"别让小朋友被 94% 吓到。
- **点名净化**：从可执行路径里抽出小朋友能看懂的名字（取 `.app` 名、去掉 Helper 后缀），避免甩出一长串带版本号的路径。

## 3. 真机验证：踩了两个"非逻辑"的坑

接入按老流程走（workspace 注册 → 构建 → 共享 profile 链接 → 装载声明），三级验证全绿。真正花时间的是**前端卡片在 harness Web 真机上跑**——这一步暴露了两个都是沙箱与渲染层的硬约束、并非逻辑 bug 的坑：

**坑 1：命令沙箱拦了 `top` / `ps`。** 在本机 workspace-write 策略下，`top -l 1` 和 `ps -axo rss=` 都返回 `Operation not permitted`，卡片一度只有"已用 — · 空闲 —"。我们改用 `memory_pressure -Q`（空闲率）+ `sysctl -n hw.memsize`（总内存）换算已用；占用榜改成用 **python3 + libproc**（`proc_listpids` + `proc_pidinfo` + `proc_name`）逐个读进程 RSS——两者都免 sudo。

**坑 2：进度条 `width` 不生效。** `.fill` 是 `<span>`，行内元素会忽略宽度，长度条看起来全是一样长。给 `.fill` 加 `display:block` 后，占用榜才真正按内存比例缩放。

**展示口径迭代**：初版逐进程展示，Chrome/Lark/Code 各有一串大小差不多的 helper，榜首高度雷同。我们改成**按 App 聚合**（同一 App 主进程 + 全部 helper 的 RSS 求和）再排名，长度条才拉开差距；顺手修了 `com.apple.*` 被 `.app` 子串误截成 `com` 的命名净化 bug。

最终卡片是「🦉 记忆小管家」：蓝色系、猫头鹰当吉祥物（和 kid-storage 的橙色大仓库区分），注册到 `conversation.input.dock` 槽，常驻页面、8 秒自动刷新、点标题可折叠，展示工作台已用百分比、压力状态和按 App 聚合的占用榜。

## 4. 结论与建议

这第 5 款插件把"内存"这块最难讲的抽象概念，稳稳落成了小朋友看得见的可爱小卡片，也把 kidlab 的"电脑启蒙"地图又拼上一块。

**关键洞察**：真机验证永远比静态检查值钱——沙箱和渲染层会以你意想不到的方式拦你，而这种坑只能靠实机跑出来。

行动建议：**发布即验证线上效果**（沿用 kidlab 的一贯规矩）；占用榜的 App 聚合逻辑值得抽成可复用子工具，并入 `mem_top`，让模型在文本侧也能引用这份排名。
